# OFFICE RAID 기술 설계서

## 기술 기준

- 엔진: Unity 6.3 LTS
- 우선 플랫폼: Android
- 기본 화면: 세로 화면, 360×780 기준 (`9:19.5`)
- 대응 비율: `9:16`~`9:21`, 노치·펀치홀 안전 영역 적용
- 첫 전투 방식: 3인 배치 후 자동 진행
- 아키텍처: Unity 의존성이 없는 Core와 화면을 담당하는 Runtime 분리

## 현재 개발 전략

게임 규칙과 UI가 자주 바뀌는 프로토타입 단계에서는 `web/`의 HTML·CSS·JavaScript 버전을 우선 수정하고 GitHub Pages에서 즉시 검증합니다. 현재 Unity 소스는 지금까지 확정된 기준점으로 유지하되, 웹 수정마다 같은 기능을 반복 구현하거나 Unity WebGL을 빌드하지 않습니다. 전투·채용·회사 성장의 핵심 흐름이 확정되면 웹에서 검증한 결과를 Core와 Runtime에 한 번에 이식하고 Android 빌드 검증을 시작합니다.

## 프로젝트 구조

```text
Assets/
  Scenes/Main.unity
  Scripts/
    Core/       게임 규칙과 데이터
    Runtime/    Unity Canvas 화면, 도트 그래픽과 입력
  Editor/       Android 세로 방향 프로젝트 설정
  Tests/
    EditMode/   핵심 규칙 테스트
docs/
  GAME_DESIGN.md
  TECHNICAL_DESIGN.md
```

## 현재 구현

### 오프닝

앱 실행 시 `Opening` 화면에서 세 장의 정적 도트 장면을 순서대로 표시합니다. `다음` 버튼으로 장면을 넘기며 마지막 장면의 `회사 이름 정하기` 또는 각 장면의 `건너뛰기`로 기존 회사 생성 화면에 진입합니다. 웹 미리보기는 같은 구조와 문구를 사용합니다.

### 회사 생성

첫 오프닝의 사무실은 배경 벽과 바닥, 창문, 시계, 수납장, 책상·모니터·빈 의자를 UI 도형으로 조립합니다. 회사 이름 입력 화면 상단에는 실제 전투 UI 대신 역광을 받은 프로젝트 보스, 세 직원의 뒷모습, 마감표와 흩날리는 서류로 구성된 포스터형 연출 장면을 표시합니다. 회사 이름 입력·랜덤 생성 뒤 대표 커스터마이징 화면으로 이동합니다. 기본 외형과 얼굴 세부 탭에서 9개 파츠를 직접 조절하거나 전체 랜덤을 사용할 수 있습니다. 대표 이름과 `AppearanceProfile`을 `OfficeRaidGame.CreateCompany`에 전달하고 대표, 영업, 개발 담당자 총 3명으로 시작합니다. 초기 보유 현금, 직원 정원과 프로젝트 참가 인원도 이 메서드에서 관리합니다.

### 면접과 외형 조합

`CandidateGenerator`는 이름, 부서, 숙련도, 능력치, 성격, 급여와 외형 파츠 인덱스를 생성합니다. `PixelArtFactory`는 얼굴 8종, 피부 6종, 머리 16종, 눈 10종, 눈썹 8종, 코 8종, 입 10종, 액세서리 9종, 의상 12종을 24×24 도트 초상화로 조립합니다. 모든 파츠 값이 스프라이트 캐시 키에 포함되어 서로 다른 조합이 같은 이미지로 재사용되지 않습니다. `Portrait`은 사무실·면접용 정면, `PortraitBack`은 프로젝트 전투용 뒷모습을 생성하며 피부·머리·의상 파츠를 공유합니다.

숙련도 기본 확률:

- 신입 60%
- 경력자 25%
- 전문가 10%
- 에이스 4%
- 업계 전설 1%

### 프로젝트 전투

`BattleSimulator`는 Unity 프레임워크와 분리된 순수 C# 규칙입니다. 직원은 속도순으로 행동하고, 속도가 같으면 팀 편성 순서를 따릅니다. 부서 능력과 추천 부서 보너스를 사용해 프로젝트의 남은 업무량을 감소시킵니다.

현재 핵심 연계:

1. 영업이 요구사항을 정리합니다.
2. PM이 팀의 모멘텀을 올립니다.
3. 개발이 정리된 요구사항과 모멘텀을 이용해 추가 업무 피해를 줍니다.

웹 프로토타입의 `DirectiveGauge`는 50에서 시작하며 직원 행동마다 속도에 따라 10~14씩 증가합니다. 돌발 상황은 12~20, 업무량 70%와 40% 도달은 각각 30을 추가합니다. 100이 되면 자동 진행을 정지하며, 모든 참가자의 유효한 스킬이 선택됐을 때만 전투를 재개합니다. 체력 구간은 보너스 충전이므로 처리량이 낮은 팀도 시간 경과만으로 발동할 수 있습니다.

Runtime과 웹은 같은 간결한 입력 흐름을 사용합니다. 전투 중에는 게이지 하나만 상시 노출하고, 일시 정지 시 전투장 위에 직원 탭 3개와 현재 직원의 선택지 3개만 표시합니다. 전원 선택 시 실행 버튼이 활성화됩니다. 긴급 지시는 일반 행동 순서와 달리 하나의 계획으로 처리하여 지원·설정 스킬, 공격 스킬, 연계 보너스 순서로 계산합니다. 분석 화면은 이 실행 순서를 먼저 표시하고, 결과 화면은 12개 스킬에 연결된 고유 CSS 모티프를 순차 재생한 뒤 `PERFECT WORKFLOW` 전체 화면 효과로 마무리합니다. 즉시 처리량, 상태 해제, 마감 연장, 자동화 지속 효과 및 스킬 연계는 기존 계산 결과를 그대로 반영합니다.

### 첫 전투 온보딩

새 회사는 면접 기능이 잠긴 상태로 시작합니다. 업종별 고정 창립팀과 첫 프로젝트 한 건만 노출하고, 전투 진입 시 업무량과 마감, 실무·협업·속도의 역할, 속도 기반 행동 순서를 단계별로 설명합니다. 첫 긴급 지시가 준비되는 순간에는 지원 → 공격 → 연계 계산 규칙을 상황에 맞춰 안내합니다. 첫 전투에서는 돌발 상황과 처리량 편차를 끄므로 화면에 표시한 수치와 실제 결과가 일치합니다. 성공 상태가 저장되면 면접과 일반 프로젝트 목록이 열립니다. 기존 저장은 프로젝트 성공 기록 또는 추가 채용 직원이 있으면 튜토리얼 완료로 이전합니다.

2일차부터 일정 확률로 프로젝트 돌발 상황이 발생합니다. 요구사항 변경은 업무량을 되돌리고 영업의 요구사항 정리를 초기화하며, 긴급회의는 당일 효율을 낮추고, 예산 삭감은 2일 동안 처리량을 감소시킵니다. 고객의 빠른 승인은 2일 동안 처리량과 모멘텀을 높입니다. `BattleSimulator`가 현재 상태 이름과 남은 기간을 제공하므로 Unity와 웹 화면에서 같은 규칙을 표시할 수 있습니다.

회사는 `SelectedProjectTeamIds`에 프로젝트 참가자 3명을 순서대로 저장합니다. 전투 시 직원 목록의 앞 3명을 임의로 쓰지 않고 저장된 팀을 불러오며, 퇴사자 ID나 잘못된 인원수는 Core 규칙에서 거부합니다.

전투 화면은 프로젝트 보스를 위쪽, 뒷모습의 직원을 아래쪽에 배치합니다. 영업의 요구사항 정리와 개발의 코드 블록은 아래에서 위로 이동하고, PM의 일정표는 팀 앞에 방어막으로 표시됩니다. 모든 도트 스프라이트는 `PixelArtFactory`가 작은 런타임 텍스처로 생성하며 `FilterMode.Point`를 사용합니다. 브라우저 미리보기는 Unity의 좌하단 원점과 HTML Canvas의 좌상단 원점 차이를 `rect` 변환 함수에서 보정해 두 버전의 상하 방향을 일치시킵니다.

### 세로 화면 대응

- `CanvasScaler` 기준 해상도: 360×780
- 모든 주요 화면: 비율 앵커 기반 배치
- `SafeAreaFitter`: `Screen.safeArea` 변경을 감지해 노치와 시스템 표시 영역 회피
- Android 방향: Portrait 고정, 가로 자동 회전 비활성화
- 긴 화면의 추가 공간은 전투장과 카드 사이 여백으로 흡수
- 웹 미리보기는 높이 560px 미만의 가로 화면에서 게임을 숨기고 세로 회전 안내를 표시
- 모바일 키보드나 분할 화면으로 세로 높이가 560px 미만이 되면 앱 내부 세로 스크롤을 허용

### 보상

프로젝트 성공 시 현금, 평판과 무작위 장비를 획득합니다. 실패 시 직원이나 장비는 잃지 않고 현금 일부만 차감됩니다.

`Equipment`는 `EquipmentSlot`과 등급, 실무·협업 보너스를 가집니다. 미장착 장비는 `CompanyState.Inventory`, 장착 장비는 `Employee.Equipment`에 저장합니다. `TryEquip`은 같은 슬롯의 기존 장비를 보관함으로 되돌린 뒤 새 장비를 장착하고, `BattleSimulator`는 `EffectiveWorkPower`와 `EffectiveCollaboration`을 사용합니다.

### 웹 자동 저장

브라우저 프로토타입은 버전이 포함된 JSON을 `localStorage`에 자동 저장합니다. 회사·직원·팀·장비·채용 후보·프로젝트와 재무 기록을 복원하며, 진행 중인 전투는 저장하지 않습니다. 전투 도중 새로고침하면 마지막으로 확정된 회사 상태로 돌아가므로 보상이 중복 지급되지 않습니다. 저장 데이터가 있으면 첫 화면에서 회사 요약과 `이어하기`, 확인 창을 거치는 `새 게임`을 표시합니다.

### 회사 확장

웹 상태의 `companyLevel`은 소형 0, 중형 1, 대형 2로 저장합니다. 단계 데이터는 정원, 프로젝트 팀 최대 인원, 요구 성과와 비용을 함께 보유합니다. 확장 구매 시 현금을 차감하고 분기 비용의 `expansion` 항목에 기록한 뒤 정원과 레벨을 즉시 저장합니다. 기존 저장에는 `companyLevel`이 없으면 저장된 정원을 기준으로 단계를 추론하며 기본 정원 6명은 소형으로 유지합니다.

프로젝트 팀은 최소 3명부터 현재 단계의 최대 인원까지 저장할 수 있습니다. 전투 계산은 고정 인원 대신 실제 `team.length`를 사용하고, 4명은 한 줄, 5~6명은 두 줄로 표시합니다. 사무실은 한 근무 구역에 최대 6명만 표시하고 이전·다음 구역을 전환해 직원 수 증가 때문에 캐릭터가 과도하게 축소되지 않도록 합니다.

## 테스트

Unity Test Runner의 EditMode에서 다음 항목을 검증합니다.

- 회사 생성 시 직원 3명 배치
- 커스텀 대표 이름·외형 적용
- 면접 후보의 외형 파츠 범위
- 초기 팀의 프로젝트 완료 가능 여부
- 강제 돌발 상황 발생과 임시 상태 적용
- 프로젝트 성공 보상 중복 방지와 지급 결과
- 공격력과 무관한 긴급 지시 게이지 보장
- 모든 참가자의 스킬 선택 검증과 전투 재개
- 속도순 행동, 동속도 편성 순서와 속도별 지시 충전량
- 긴급 지시의 지원 우선 계산과 첫 전투 면접 해금
- 기존 저장 데이터의 튜토리얼 완료 상태 이전
- 확장 조건·비용 차감·정원과 팀 최대 인원 변경
- 기존 저장 데이터의 회사 단계 이전과 확장 비용 결산 반영
